# Use Case Specification

---

# UC-01 — Оформлення замовлення в їдальні через QR-ідентифікацію студента

| Field | Description |
|---|---|
| Use Case ID | UC-01 |
| Use Case Name | Оформлення замовлення через QR |
| Primary Actor | Кухар |
| Secondary Actors | Студент, Система |
| Scope | QR Lunch Ordering System |
| Level | User Goal |

---

# 🎯 Мета

Ідентифікувати студента, оформити замовлення, списати кошти з балансу та зафіксувати транзакцію в системі.

---

# Preconditions

- Кухар авторизований у системі
- Меню доступне для оформлення замовлень
- Студент зареєстрований у базі даних
- Студент має унікальний QR-код

---

# Trigger

Студент сканує QR-код на точці видачі, після чого система відкриває картку студента на екрані кухаря.

---

# Main Success Scenario

1. Студент сканує QR-код
2. Система знаходить профіль студента
3. Дані студента відображаються кухарю:
   - ПІБ
   - група
   - баланс
4. Студент повідомляє бажані страви
5. Кухар обирає страви та кількість у веб-інтерфейсі
6. Система автоматично розраховує загальну суму замовлення
7. Кухар підтверджує замовлення
8. Система перевіряє достатність балансу
9. Система списує кошти з рахунку студента
10. Система створює транзакцію
11. Система зберігає транзакцію в базі даних
12. Система відображає повідомлення про успішну оплату
13. Система оновлює баланс студента
14. Кухар видає обід студенту

---

# Postconditions

## Success Postconditions

- Транзакція збережена в системі
- Баланс студента оновлений
- Дані замовлення доступні для звітності

## Failure Postconditions

- Транзакція не створена
- Баланс не змінений
- Операція позначена як failed або canceled

---

# Alternative Flows

## A1 — Студента не знайдено

1. Система не знаходить студента
2. Відображається повідомлення:

```text
Студента не знайдено
```

3. Процес завершується

---

## A2 — Недостатньо коштів

1. Система перевіряє баланс
2. Баланс недостатній
3. Відображається повідомлення:

```text
Недостатньо коштів
```

4. Кухар може:
   - змінити замовлення
   - скасувати операцію

---

## A3 — Скасування замовлення

1. Кухар скасовує операцію до підтвердження
2. Замовлення не створюється
3. Списання коштів не виконується

---

## A4 — Некоректний QR-код

1. Система не може зчитати QR
2. Відображається повідомлення:

```text
QR недійсний
```

3. Система повертає користувача до повторного сканування

---

# Exception Flows

## E1 — Помилка списання коштів

1. Під час оплати виникає помилка
2. Транзакція не створюється
3. Баланс не змінюється
4. Відображається повідомлення про помилку

---

## E2 — Система недоступна

1. Система стає недоступною
2. Відображається повідомлення:

```text
Система тимчасово недоступна
```

3. Процес завершується

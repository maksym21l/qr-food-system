# Stakeholders — QR Food System

---

## Stakeholder Table

| Stakeholder | Role | Interest | Influence |
|-------------|------|----------|-----------|
| Student | End user | Fast payment at the counter without cash or manual records | High |
| Cook | System operator | Fast order processing to serve students quickly without manual errors | High |
| Accountant | Report consumer | Automatic report generation for any period instead of manual data entry | Medium |
| Administrator | System manager | Manage products, prices and user accounts in the system | High |
| University | Project owner | Automated and transparent meal accounting across the cafeteria | High |

---

## Stakeholder Descriptions

### Student
The student is the main end user of the system. Previously students had to make advance records or carry cash. The system allows the student to simply show a QR code at the counter and pay instantly. The student wants the process to be fast and convenient.

### Cook
The cook operates the system at the cafeteria counter. Previously meals were recorded manually on paper which caused errors and slowed down the queue. The cook wants the system to work fast so students can be served as quickly as possible.

### Accountant
The accountant uses monthly reports to track cafeteria transactions. Previously all data had to be collected and written manually. The system automatically generates reports for any selected period which saves time and reduces errors.

### Administrator
The administrator manages the system — adds products, sets prices, and creates user accounts. The administrator needs a simple and reliable admin panel.

### University
The university is the owner of the project. The university is interested in transparent and automated meal accounting without manual processes and human errors.
